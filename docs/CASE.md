# Основание и текущие границы решения

Требования взяты из сообщения пользователя **«Кейс: Agentic AI для прогнозирования выработки ВЭС»**. Задача — прогнозировать почасовую выработку на 24–48 часов и воспроизвести ежедневные выпуски в феврале 2026 года, используя только погодные прогнозы, доступные на момент соответствующего выпуска.

После первоначального MVP команда передала реальные CSV, архивы проекта и Git bundle. Они проверены отдельно: [DATA_AUDIT.md](DATA_AUDIT.md) и [ARCHIVE_AUDIT.md](ARCHIVE_AUDIT.md). К существующему интерфейсу подключены данные, погодный кеш, native-модель CatBoost и сохранённые прогнозы из полного архива.

## Требования и реализация

| Требование кейса | Текущее состояние |
|---|---|
| История с марта 2023 по январь 2026 | Предоставлены два 10-минутных CSV с 11.03.2023 до 31.01.2026 23:50 |
| Подготовка почасовой мощности | Основной импорт использует только полные часы из шести измерений; всего 48 452 строки для двух турбин |
| Модель мощности | Подключена CatBoost из проекта; базовая кривая мощности сохранена для обычного CSV/демо |
| Погода по координатам | Есть адаптер Single Runs API и проверяемый кеш проекта с конкретными выпусками ECMWF |
| Горизонт 24–48 часов | Почасовые результаты отдельно для обеих турбин, с датой выпуска и происхождением данных |
| Самостоятельный цикл | Проверки входов → погода → модель/явно обозначенный сохранённый результат → анализ → сохранение; повторная проверка входов |
| Историческая доступность погоды | Временные ограничения проверяются по метаданным, но происхождение и время реальной публикации ещё не доказаны |
| Точность за февраль | Не вычисляется: факты февраля не предоставлены |

Сохранённый расчёт из архива не выдаётся за новый запуск модели. Worker для повторного прогноза читает **native CBM**, а не joblib/pickle; Python-код из переданного архива не исполняется. Если среда CatBoost не найдена, допустимо только явно обозначенное чтение сохранённого прогноза подходящего выпуска. Если такого прогноза нет, возвращается ошибка.

## Данные и проверка модели

Турбина 1: 142 360 исходных строк и 23 667 полных часов. Турбина 2: 149 499 строк и 24 785 полных часов. `ID` в исходном CSV — номер строки, а не турбина. Февральских значений мощности в этих файлах нет.

В отчёте проекта финальная CatBoost обучена на 36 632 строках погодного датасета. Выбор модели сделан на декабрьской проверке; январские прогнозы сохранены отдельно. Для выбранной модели по **2928 сохранённым январским прогнозам** независимо пересчитаны:

- MAE: `0.18603061746927146` доли нормализованной мощности;
- RMSE: `0.25715671703426574`;
- это около 18,60 и 25,72 процентного пункта соответственно.

Подтверждена арифметика сохранённых результатов, **не независимое повторное обучение январской модели**. Полный новый расчёт и совпадение с архивом нельзя считать проверенными лишь по наличию worker: выполненные проверки фиксируются в [VERIFICATION.md](VERIFICATION.md).

Ошибка простой кривой на измеренном ветре относится к базовому режиму и не смешивается с январскими прогнозными метриками CatBoost. Интервалы проекта используют январские ошибки с целевым покрытием 80%; покрытие следующего периода не гарантируется.

## Явные временные предположения

| Параметр | Подключённый проект | Базовый CSV/демо |
|---|---|---|
| Часовой пояс сценария | UTC, как в конфигурации архива | UTC+5 по исходной конфигурации MVP |
| Момент ежедневного выпуска | 23:00 UTC | 23:00 UTC+5 |
| Задержка публикации погоды | Предполагаемые 8 часов | Предполагаемые 12 часов |
| Получение погоды | Локальный кеш проекта | Архивный API либо явно синтетическая погода |

В исходных CSV часовой пояс отсутствует. UTC и начало 10-минутного интервала сохраняются для воспроизводимости переданного проекта, но **не подтверждены источником данных**. Для часового агрегата доступность учитывается не раньше завершения интервала; последний час 31 января нельзя использовать в выпуске 23:00, если он ещё не завершён.

Время `run_time` — инициализация погодной модели. Правило `available_at = run_time + 8 часов` не доказывает, что конкретный прогноз был опубликован тогда. Вопрос оперативного происхождения раннего ECMWF-архива, обозначаемого как hindcast, остаётся открытым. Контрольные суммы подтверждают внутреннюю целостность материалов, а не их историческую доступность.

Финальная модель не применяется к моментам раньше её обучающей отсечки. Февральские факты не используются для обновления, выбора модели или построения признаков. При подтверждении другой временной конвенции потребуются повторная подготовка данных, обучение и проверка.

## Прогнозный период и единицы

Сценарий проекта содержит выпуски 31 января и 1–28 февраля — 29 моментов. При горизонте 48 часов последний выпуск включает март; в февральский экспорт попадают только цели внутри `[2026-02-01, 2026-03-01)` UTC. Выпуски и пересекающиеся горизонты сохраняются раздельно. Submission берёт первые 24 часа каждого выпуска: 672 часа × 2 турбины.

В интерфейсе показывается нормализованная мощность 0–100%. Номинальные мощности турбин не предоставлены, поэтому физические МВт и МВт·ч не вычисляются. «Среднее двух турбин» — среднее двух нормализованных значений с равными весами.

Координаты из сообщения команды: турбина 1 — `43.6451388889, 78.5356111111`, турбина 2 — `43.6431944444, 78.5388333333`. Для второй долготы принято восточное направление по соседнему расположению первой. Координаты погодной сетки фиксируются отдельно от положения турбин.

## Что ещё нужно подтвердить

1. Часовой пояс исходных CSV, историческое изменение смещения, смысл метки и задержку телеметрии.
2. Оперативное происхождение погодных запусков и свидетельства их публикации до момента прогноза.
3. Независимое воспроизведение обучения и январской проверки; после получения отдельных фактов — оценку февраля.
4. Формат сдачи, метрику жюри, точное время выпуска и трактовку горизонтов.
5. Номинальные мощности, высоту ветра/ступицы и сведения о простоях, если они нужны для физической выработки и повышения качества.

LLM явно не требуется в переданном условии; текущий агент выполняет детерминированный управляющий цикл с ML-моделью. Вопросы источников и времени сохраняются как ограничения в интерфейсе и экспорте: `competition_ready=false`. Полное соответствие кейсу пока не заявляется.
