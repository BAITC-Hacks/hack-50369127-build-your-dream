# Wind Forecast · HackAlem AI

Команда **Build_your_dream**. Репозиторий хакатона:
[BAITC-Hacks/hack-50369127-build-your-dream](https://github.com/BAITC-Hacks/hack-50369127-build-your-dream).

Воспроизводимый прогноз нормализованной мощности двух ВЭУ на 24–48 часов.
Архивные выпуски ECMWF IFS HRES → признаки → CatBoost → неопределённость →
автономный контроллер → CSV и интерактивный отчёт.

**Начните с `reports/demo.html`: он открывается в браузере без интернета.**
В пакет включены исходные CSV, погодный кэш, модель и февральские прогнозы.

## Быстрый запуск

Python 3.10+; проверено на Python 3.12, CPU. Команды выполняются из каталога run.py.

```bash
python -m venv .venv
```

Активация Windows PowerShell: `.\.venv\Scripts\Activate.ps1`.
Активация Linux/macOS: `source .venv/bin/activate`.

```bash
python -m pip install -r requirements-models.txt
python run.py
```

По умолчанию используются сохранённая модель и кэш.

| Файл | Назначение |
|---|---|
| reports/demo.html | Самодостаточная демонстрация, выбор даты и турбины |
| outputs/submission_february.csv | 1344 строки: 672 часа × 2 турбины, горизонт 1–24 часа |
| outputs/forecast_all_issues.csv | Все 29 запусков × 48 часов × 2 турбины = 2784 строки |
| outputs/agent.sqlite | Версии запусков и журнал решений |
| reports/training_report.json | Выбор модели, метрики, границы выборок |
| reports/january_predictions.csv | Факты и прогнозы независимой проверки |

Полное воспроизведение подготовки, обучения и replay из кэша:

```bash
python run.py --train
```

Разрешить сетевые загрузки: `python run.py --train --online`.
Подробности телеметрии, кэша и схемы данных: `docs/DATA_PIPELINE.md`.
Шесть недоступных августовских выпусков исключены с записью причин в манифест.
Все февральские выпуски доступны. Агент не публикует неполную суточную таблицу.

## Отдельные команды

```bash
python -m src.data.build_features --telemetry-only
python -m src.models.train
python -m src.agent.run --offline
python -m src.agent.run --issue-time 2026-01-31T23:00:00Z --offline
python -m src.agent.run --issue-time 2026-02-01T05:00:00Z
python -m src.report
python -m unittest discover -s tests -v
python -m src.verify
```

Второй момент расчёта показывает пересчёт после поступления нового погодного
выпуска. Каждый прогноз сохраняет собственные issue_time и run_time. Данные,
появившиеся позднее, не подставляются в прежний исторический расчёт.

## Методика

- Январь–ноябрь 2025: обучение.
- Декабрь 2025: выбор между средней мощностью, монотонной кривой мощности и
  CatBoost глубины 4/6 с потерями MAE/RMSE.
- Январь 2026: независимая проверка выбранной конфигурации после обучения
  на информации, доступной до первого январского выпуска.
- Февраль 2026: модель заморожена на информации, доступной 31 января в 23:00 UTC.

Цель часа доступна только после окончания часа. При выборе модели, обучении
и калибровке исключаются ещё не завершившиеся часы. Целевые часы разных частей
выборки не пересекаются. Прогнозы, выпущенные до готовности модели, исключаются
из её оценки. Случайного train/test split нет.

Входы: прогнозная погода, турбина, горизонт, календарные и физические признаки.
Фактические ветер/температура и будущая мощность в признаки не входят.
MODEL_FEATURES задаёт явный список входов. Повтор целевого часа в разных выпусках
сохраняется как отдельная прогнозная задача. В CatBoost веса компенсируют число
повторов turbine/valid_time. MAE/RMSE выводятся по ВЭУ и горизонтам 1–24/25–48.

## Неопределённость

Эмпирические симметричные интервалы целевого покрытия 80% строятся по абсолютным
остаткам отдельно для ВЭУ и горизонта. Для январской проверки калибровка сделана
на декабре; для февраля — на январских прогнозах модели, не обученной на январе.
Покрытие не гарантировано при сдвиге распределения и зависимости ошибок.
При откате к старому выпуску интервал расширяется по явной эвристике; возраст
такого выпуска виден в fallback_age_hours. Фактическое покрытие января показано в отчёте.

## Автономность и Agentic AI

Контроллер выполняет PLAN → FETCH → VALIDATE → PREDICT → ANALYZE → PUBLISH.
При сбое: OBSERVE → REPLAN → более ранний выпуск → повторная проверка.
Максимальный откат — 12 часов. После исчерпания вариантов возвращается ошибка.

Обычный режим использует детерминированную политику и обученную ML-модель.
Дополнительно реализован ограниченный LLM-планировщик через OpenAI API:

```bash
python -m src.agent.run --issue-time 2026-01-31T23:00:00Z --offline --llm
```

Для него задайте OPENAI_API_KEY переменной окружения, не сохраняйте ключ в файлах.
OPENAI_MODEL задаёт модель; по умолчанию gpt-4.1-mini. Флаг offline отключает
только погодные запросы; llm требует соединения с OpenAI. Планировщик получает
диагностику и выбирает разрешённое действие. Он не изменяет численные прогнозы.
Живой вызов LLM не проверен: ключ не предоставлялся. Включённый февральский replay
выполнен детерминированным контроллером.

SQLite хранит события, входные хэши и хэш модели. Неизменный запрос возвращает
сохранённый прогноз; новый выпуск/модель/политика создаёт новую версию.
Загружайте joblib только из доверенного источника: это Python-десериализация.

## Соглашения и ограничения

1. UTC и начало 10-минутного интервала приняты как предположения. CSV не содержат
   часовой пояс. Настройки находятся в config/config.yaml.
2. Задержка публикации погоды 8 часов — предположение; availability_verified=False.
   Строгий режим требует реальные свидетельства доступности и останавливается без них.
3. Документация Open-Meteo упоминает hindcasts. Наличие архива не доказывает исходное
   время публикации. ECMWF внедрил IFS 49r1 12 ноября 2024; использованный период
   начинается позже, однако происхождение конкретных архивных файлов не подтверждено.
   Полное соответствие требованию as-issued остаётся неподтверждённым.
4. Номинальные мощности ВЭУ не предоставлены. Выдача — нормализованная мощность
   каждой ВЭУ. farm_equal_weight_index.csv — среднее при предположении равных весов,
   а не проверенная суммарная генерация станции или МВт.
5. Фактической генерации февраля нет; февральские MAE/RMSE не заявляются.
6. Это проверенный исследовательский прототип для хакатона. Развёртывание у заказчика
   и подключение промышленной SCADA не выполнены.
