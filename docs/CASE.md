# Основание проекта

Источник требований: сообщение пользователя **«Кейс: Agentic AI для прогнозирования выработки ВЭС»**, разделы «Описание задачи», «Предоставляемые данные», «Задача участников» и заключительное требование о доступности архивного прогноза.

В исходном репозитории был только README с названием команды. Истории, схемы выгрузки, кода, тестов и критериев начисления баллов не было. Приложенная памятка `Pasted text.txt` требует рабочего MVP, понятного объяснения, проверок и сценария демонстрации; это инструкции по работе, не дополнительные метрики кейса.

## Обязательная часть из условия

- История ВЭС с марта 2023 по 31 января 2026 включительно.
- Входы: статистическое время, средняя скорость ветра, нормализованная активная мощность, средняя температура.
- Почасовой прогноз на 24–48 часов; тестовый период 1–28 февраля 2026.
- Внешняя погода автоматически получается по координатам.
- Полный цикл: погода → подготовка → модель → почасовой прогноз → анализ → повторный расчёт при изменении входов.
- Последовательные выпуски начиная с 31 января. Погода должна быть прогнозом, доступным на момент выпуска, а не фактом, известным позднее.

## Наши явные допущения

- Python без внешних зависимостей и обучаемая эмпирическая кривая мощности — базовый, объяснимый метод. Сравнение с более сложными методами на реальных данных ещё не проводилось.
- Выпуск ежедневно в 23:00 UTC+5; это даёт полные календарные следующие сутки. Точное время организаторами не задано.
- Восточная долгота второй турбины принята по соседнему расположению первой.
- Прогноз пока в долях нормализованной мощности. Мощности турбин неизвестны, поэтому сумма в МВт и энергия в МВт·ч отсутствуют.
- История тестового месяца не поступает в обучение. Использование фактов февраля для обновления модели не разрешено условием явно, поэтому модель заморожена после января.
- Время доступности телеметрии принимается равным её метке, для агрегата — последнему измерению. Это нужно сверить с поставщиком данных.
- 12 ч задержки погодного выпуска — консервативная настройка, не подтверждённое расписание конкретного архива.

## Что не предоставлено

Путь к истории, пример исходной таблицы, срок сдачи, формат submission, метрика жюри, точный момент выпуска, часовой пояс выгрузки, шкала нормализации, номинальные мощности, высота измерения ветра и журналы доступности погоды. Эти сведения нельзя восстановить из координат.

## План проверки MVP

1. Проверка CSV: неверные числа, шкала, дубликаты, пропуски, подчасовая агрегация.
2. Проверка модели: временное разделение, исключение будущих меток, ограниченная мощность и базовые сравнения.
3. Проверка погоды: точный выпуск, допустимое время доступности, полный горизонт, ошибка вместо скрытой подмены.
4. Сквозное демо: импорт → прогноз → обновление → 29 выпусков → 672 часа на турбину → CSV.
5. Проверка браузером: пустой экран, кнопки, график, ошибки, экспорт и сохранение состояния.

Соответствие строгому историческому источнику и точность на ВЭС остаются незакрытыми до получения данных и подтверждения архивного происхождения. Это отражается в интерфейсе и выгрузках.
