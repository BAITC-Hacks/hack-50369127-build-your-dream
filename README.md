# Wind Agent · Build your dream

Локальный MVP для кейса **«Agentic AI для прогнозирования выработки ВЭС»**. Программа учится на истории двух турбин, получает погодные данные по координатам, рассчитывает нормализованную мощность на 24–48 часов и сохраняет журнал решений и происхождение входных данных.

**Текущий статус:** рабочий учебный цикл и адаптер архивной погоды. Реальной истории ВЭС в репозитории нет. Учебные результаты синтетические. Архив Open-Meteo требует проверки оперативного происхождения и исторического времени публикации, поэтому ни один текущий результат не помечается готовым к сдаче. Точность на реальной ВЭС не измерена.

## Быстрый запуск

Нужен Python **3.11 или новее**. Внешних Python-библиотек, Node.js, ключей API и платных сервисов нет. Команды выполняются **из корня этого репозитория** в PowerShell или терминале.

```powershell
python -B -m windagent serve
```

Откройте **http://127.0.0.1:8080**. Нажмите «Открыть демо»: история, модель и первый прогноз создадутся автоматически. Учебный режим работает без интернета. Если порт занят:

```powershell
python -B -m windagent serve --port 8081
```

Программа слушает только `127.0.0.1`. Остановка — `Ctrl+C`. Результаты сохраняются в `runtime/` и исключены из Git. На Windows, если папка «Документы» запрещает приложению запись, используется отдельная папка `%TEMP%/wind-agent/<идентификатор проекта>`: точный путь выводится в терминале и `/api/state`. Для постоянного хранения можно явно задать доступную папку через `--workspace` **перед** командой. Явно заданный путь не заменяется автоматически.

Полный учебный цикл из терминала:

```powershell
python -B -m windagent demo --backtest
python -B -m windagent export --kind submission --output runtime/submission-demo.csv
python -B -m unittest discover -s tests -v
```

Если Windows запрещает запись в `runtime`, для экспорта укажите доступную папку, например `--output "$env:TEMP/submission-demo.csv"`. Не запускайте демо поверх импортированной реальной истории: для него предусмотрено отдельное рабочее пространство.

## Что уже реализовано

- Веб-панель на русском: загрузка CSV, график, выбор турбины и горизонта, таблица часов, журнал агента, CSV-экспорт.
- Строгая подготовка данных: явная шкала мощности, проверка времени и чисел, обнаружение конфликтующих дубликатов, часовая агрегация, отчёт о пропусках.
- Отдельная обучаемая кривая мощности для каждой турбины. Агент выбирает ширину интервалов скорости ветра по последним 20% истории и сравнивает результат с постоянным средним. Используется приближённая температурная поправка плотности воздуха.
- Сравнение с простым прогнозом «последняя известная мощность сохранится». Ошибка проверки модели с **измеренной** погодой отделена от точности настоящего прогноза.
- Получение отдельных запусков погодной модели по координатам, кеш исходных ответов, ограниченные повторы при сбоях, контроль горизонта и временных ограничений.
- Автоматический последовательный ретропрогноз февраля, сохранение дат выпуска и контроль 672 часов на турбину.
- Повторный расчёт при изменении истории или погоды. При неизменных входных данных агент возвращает сохранённый результат.
- Отдельная команда оценки по фактической мощности, которая не передаёт февральские метки в обучение.

Агент — **детерминированный управляющий цикл с моделью**, без LLM. Он сам проверяет данные, выбирает модель, вызывает погодный инструмент, принимает решение о повторном расчёте, анализирует прогноз и сохраняет результат. Если жюри требует именно LLM-агента, это дополнительное требование нужно подтвердить: в переданном условии его нет. Пошаговый сценарий выступления — [docs/DEMO.md](docs/DEMO.md).

## Реальные данные

Веб-панель принимает CSV UTF-8. Excel можно сохранить как CSV UTF-8; непосредственный импорт XLSX пока не реализован. Один файл должен содержать обе турбины с идентификаторами `1` и `2`.

```csv
timestamp,turbine_id,wind_speed,temperature,power
2026-01-01T00:00:00+05:00,1,5.2,-4.1,0.14
2026-01-01T00:00:00+05:00,2,5.4,-4.0,0.15
```

Это **предлагаемый входной формат приложения**, а не утверждение о формате файлов организаторов. [data/example.csv](data/example.csv) показывает только структуру: четырёх строк недостаточно для обучения. Для запуска нужно минимум 48 доступных часов каждой турбины; для содержательной проверки нужна полноценная история.

| Поле | Смысл |
|---|---|
| `timestamp` | ISO 8601 с поясом; лучше использовать явные `+05:00`, `+06:00` или `Z` из исходной системы |
| `turbine_id` | `1` или `2` |
| `wind_speed` | Средняя скорость ветра, м/с |
| `temperature` | Средняя температура, °C |
| `power` | Нормализованная активная мощность 0–1 |

Распознаются названия столбцов из условия на русском, разделители запятая, точка с запятой и табуляция; десятичная запятая допустима в корректно разделённом CSV. Если исходная мощность 0–100, задайте делитель `100`. Приложение не угадывает шкалу по максимуму данных.

```powershell
python -B -m windagent import "D:/данные/history.csv" --timezone-offset 5 --power-scale 1
python -B -m windagent forecast --as-of "2026-01-31T23:00:00+05:00" --hours 48 --mode archive
python -B -m windagent backtest --hours 48 --mode archive
python -B -m windagent export --kind backtest --output runtime/all-origins.csv
python -B -m windagent export --kind submission --output runtime/submission.csv
```

`--timezone-offset 5` — явное допущение для дат **без** указанного пояса; смещение из самой даты всегда имеет приоритет. Для истории 2023–2026 нельзя без проверки считать, что фиксированное смещение подходит всем строкам. Уточните, хранит ли выгрузка UTC, местное историческое время или время контроллера.

Подчасовые значения усредняются внутри часа UTC. Доступность агрегата наступает после последнего входящего измерения; он не попадёт в более раннее обучение. Среднее арифметическое корректно для равномерной частоты: нерегулярные интервалы требуют отдельной обработки. Часовые значения считаются известными к своей метке; если это начало интервала или есть задержка телеметрии, времена необходимо исправить до импорта.

МВт и МВт·ч не вычисляются без номинальных мощностей. «Среднее двух турбин» в интерфейсе — среднее нормализованных значений, а не физическая выработка станции при неизвестных мощностях.

## Как воспроизводится февраль

Настройки находятся в [config.json](config.json). Координаты из сообщения команды переведены в десятичные градусы:

| Турбина | Широта | Долгота |
|---|---:|---:|
| 1 | 43.6451388889 | 78.5356111111 |
| 2 | 43.6431944444 | 78.5388333333 |

Для второй долготы принято восточное направление, как у соседней первой турбины. Время сценария принято UTC+5; время выпуска — **23:00 местного времени**. Тогда выпуск 31 января прогнозирует часы 1 февраля 00:00 — 2 февраля 23:00 при горизонте 48 часов. Это выбранная нами конвенция, а не заданное организаторами время выпуска.

Обучение ограничено `2026-01-31T23:00:00+05:00`, даже если загружены февральские строки. При более раннем выпуске отсечение автоматически сдвигается назад. В феврале модель заморожена: измерения тестового месяца не требуются и не используются. При обновлении допустимой январской истории модель пересчитывается.

Выполняются **29 выпусков**: 31 января и каждый день 1–28 февраля. Выпуск 28 февраля сохраняется в журнале и прогнозирует март. В февральские выгрузки попадают только даты `[1 февраля, 1 марта)`:

- `backtest`: все пары «выпуск — прогнозный час»; для 48 ч это 2640 строк на две турбины. Перекрывающиеся горизонты сохранены отдельно.
- `submission`: первые 24 часа каждого выпуска, одна строка на турбину и час, **1344 строки = 672 × 2**. Это прозрачная предварительная схема, которую нужно сверить с форматом сдачи организаторов.
- `forecast`: последний выпуск, включая март, если он запущен 28 февраля.

В каждой строке сохраняются время выпуска, целевой час, горизонт, выпуск погоды, основание доступности, хеш погоды, хеш модели и флаг учебного/архивного режима. `competition_ready=false` честно обозначает незакрытые условия, а не качество прогноза.

## Архив погоды и отсутствие будущей информации

Используется точный `run=` [Open-Meteo Single Runs API](https://open-meteo.com/en/docs/single-runs-api), а не фактическая погода ERA5 и не ряд, склеенный из последних запусков. Подробности, высота ветра, ссылки и ограничения — [docs/WEATHER.md](docs/WEATHER.md).

`run_time` — инициализация погодной модели, не дата публикации. Для выбора выпуска применяется консервативная задержка из конфигурации, по умолчанию 12 часов. **Это допущение, не историческое доказательство доступности.** Документация также обозначает раннюю серию ECMWF как hindcasts. Пока оперативное происхождение конкретных февральских запусков и их доступность не подтверждены, архивный расчёт нельзя представлять как окончательно соответствующий этому пункту кейса.

При отсутствии погоды, повреждении ответа, неполном горизонте или данных из будущего расчёт завершается ошибкой. Синтетика и фактическая погода не подставляются вместо отсутствующего архивного прогноза.

## Обновления и оценка

Кнопка проверки обновлений повторно получает выбранный архивный выпуск. Агент сравнивает содержимое данных, а не время HTTP-запроса. Для автоматического наблюдения за выбранным историческим моментом:

```powershell
python -B -m windagent watch --as-of "2026-01-31T23:00:00+05:00" --hours 48 --interval 300 --history "D:/данные/history.csv"
```

Команда проверяет погоду каждые 300 секунд и повторно импортирует файл при изменении его содержимого. Момент `--as-of` фиксирован; это наблюдение за обновлениями входов выбранного сценария, не планировщик текущих ежедневных запусков. `--iterations 1` выполняет один цикл, `Ctrl+C` останавливает наблюдение.

При наличии отдельно предоставленных фактов февраля:

```powershell
python -B -m windagent evaluate --forecast runtime/all-origins.csv --actuals "D:/данные/february-actuals.csv"
```

Факты используют тот же CSV-формат. Выводятся MAE (средняя абсолютная ошибка), RMSE (ошибка с большим штрафом за крупные промахи) и сравнение с последней известной мощностью, отдельно по турбинам и горизонтам 1–24 / 25–48 ч. Единица — доля нормализованной мощности; `0.05` означает 5 процентных пунктов. Пропущенные факты учитываются в отчёте; оценки по неполному покрытию не называются полными.

Полоса на графике построена по ошибкам модели на истории с **измеренной** погодой. Это не калиброванный интервал вероятности: дополнительная ошибка погодного прогноза в неё не включена. Последние 20% используются для выбора модели; их оценки не являются независимым финальным тестом.

## Проверки и структура

```powershell
python -B -m unittest discover -s tests -v
node --check web/app.js
```

Node нужен только для необязательной синтаксической проверки JavaScript. Тесты используют временные файлы и подменённые ответы API; они не требуют интернета и не доказывают доступность внешнего сервиса.

| Файл | Назначение |
|---|---|
| `windagent/data.py` | Импорт и контроль качества истории |
| `windagent/model.py` | Обучение, временная проверка, прогноз мощности |
| `windagent/weather.py` | Архив погоды, выбор выпуска, кеш и происхождение |
| `windagent/agent.py` | Решения агента, версии входов, ретропрогноз и экспорт |
| `windagent/server.py`, `web/` | Локальная веб-панель |
| `windagent/evaluate.py` | Отдельная оценка по фактической мощности |
| `tests/` | Проверки данных, времени, модели и полного цикла |
| `docs/CASE.md` | Условия кейса, допущения и незакрытые вопросы |

## Перед сдачей

1. Получить реальную историю, уточнить время, шкалу мощности, идентификаторы турбин и смысл часовой метки.
2. Подтвердить источник **оперативных** погодных выпусков, доступных в январе–феврале 2026, включая время публикации. При необходимости заменить адаптер.
3. Уточнить высоту измеренного ветра и высоту турбины; сопоставить распределения SCADA и прогнозной погоды. Текущая кривая на измеренном ветре может быть смещена при подаче модельного ветра.
4. Проверить качество на последовательных исторических прогнозах до февраля и затем на фактах февраля, если они разрешены только для финальной оценки.
5. Сверить время выпуска, формат сдачи и метрику организаторов. При предоставлении номинальных мощностей добавить физическую выработку.

Дополнительно после рабочего базового решения: обучение на архивных погодных признаках, коррекция систематической ошибки ветра, учёт простоев/обледенения, ансамбль моделей и калибровка интервалов. Они пока не реализованы.
