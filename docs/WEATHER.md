# Погода: точные запуски и ограничение проверки доступности

Клиент `windagent/weather.py` получает прогноз конкретного запуска ECMWF IFS
через [Open-Meteo Single Runs API](https://open-meteo.com/en/docs/single-runs-api).
Он не подменяет прогноз фактической погодой, ERA5 или склеенным рядом из разных
запусков. Однако **этот источник в текущей интеграции не подтверждает выполнение
строгого условия соревнования о доступности данных на момент прогноза**.

## Что запрашивается

- Endpoint: `https://single-runs-api.open-meteo.com/v1/forecast`.
- `models=ecmwf_ifs`, `run=YYYY-MM-DDTHH:MM` — точное время инициализации в UTC.
- `hourly=wind_speed_100m,temperature_2m`, `wind_speed_unit=ms`,
  `temperature_unit=celsius`, `timezone=UTC`, `timeformat=iso8601`.
- `start_date` и `end_date` ограничивают календарные дни ответа. Клиент выбирает
  только часы `as_of + 1 час` … `as_of + horizon часов` и требует каждый из них.
- Каждый объект ВЭС запрашивается отдельно: T1 `(43.6451388889, 78.5356111111)`,
  T2 `(43.6431944444, 78.5388333333)`.

ECMWF IFS использует сетку примерно 9 км; эти две близкие турбины могут получить
одну и ту же ячейку. Скорость на 100 м — выбранный модельный признак, а не
подтвержденная высота ступицы турбин. Температура относится к 2 м.
Сопоставление с измерениями станции и калибровка потребуются после получения
реальных данных. О переменных, сетке и временном разрешении:
[официальное описание ECMWF API](https://open-meteo.com/en/docs/ecmwf-api).

## Время запуска не равно времени публикации

По документации Single Runs, глобальная модель обычно вычисляется несколько
часов после инициализации; архив ECMWF начинается 14 марта 2024 года. Другие
модели в этом API архивируются только с апреля 2026, поэтому здесь они не
используются. Документация называет раннюю часть ECMWF-архива hindcasts Cycle
49R1. Определение источником конкретного запуска как операционного или
ретроспективно пересчитанного требует дополнительного подтверждения.
[Источник: Single Runs](https://open-meteo.com/en/docs/single-runs-api).

Политика клиента по умолчанию:

```text
run = последний цикл 00 / 06 / 12 / 18 UTC, удовлетворяющий run + 12 ч <= as_of
available_at = run + 12 ч   # ДОПУЩЕНИЕ, НЕ ФАКТ ИСТОРИЧЕСКОЙ ПУБЛИКАЦИИ
```

Например, `as_of=2026-01-31T23:00:00+05:00` означает 18:00 UTC. Клиент выбирает
запуск 06:00 UTC того же дня и возвращает первый целевой час 19:00 UTC,
соответствующий полуночи 1 февраля по UTC+5. Задержка 12 ч выбрана разработчиком
консервативно; она не является SLA поставщика, не учитывает доказанным образом
исторические сбои и может настраиваться. Значения ниже 12 ч вызывают отдельное
предупреждение.

Open-Meteo публикует метаданные `last_run_availability_time` для последнего
запуска. Метаданные последнего запуска сегодня не доказывают доступность
конкретного запуска в январе/феврале 2026. Поставщик также предупреждает о
задержках репликации между серверами.
[Источник: Model Updates](https://open-meteo.com/en/docs/model-updates).

Поэтому каждая запись provenance явно содержит:

```json
{
  "availability_basis": "assumed_conservative_lag_not_historical_publication_evidence",
  "availability_verified": false,
  "operational_run_verified": false,
  "competition_ready": false
}
```

Чтобы заявлять строгую воспроизводимость, нужны доказательства происхождения
каждого операционного запуска и его публикации до `as_of`: например, архив
поставщика с историческим журналом публикаций либо собственные сохраненные
в тот момент ответы и временные метки. SHA-256 сегодняшнего скачивания
подтверждает целостность сохраненного ответа, но не доказывает его прошлую
доступность. API был публично представлен в мае 2026; использование его сегодня
для получения архива само по себе не доказывает наличие тех же данных в API
в феврале.
[Источник: сообщение разработчика API](https://openmeteo.substack.com/p/single-runs-api).

## Кеш, валидация и ошибки

Ключ кеша — SHA-256 полного URL. Рядом хранятся исходные байты JSON и метаданные
URL, SHA-256, `retrieved_at`. Повторный запрос использует тот же ответ; `refresh`
снова получает тот же выбранный запуск и позволяет заметить исправление данных.
Неизменяемые копии каждого ответа сохраняются в `raw/<sha256>.json`; путь
`raw_path` включен в provenance. Обновление URL-кеша не удаляет старые копии.
Несовпадение хеша или неполный кеш завершают операцию ошибкой. Имя турбины
никогда не используется как путь файла.

Проверяются UTC, единицы, одинаковая длина массивов, уникальность временных
меток, наличие всех целевых часов и конечность чисел. Пустые, пропущенные или
аномальные значения не заполняются фактами будущего. Сетевые ошибки имеют
не более трех попыток по 20 секунд; постоянные HTTP-ошибки не повторяются.
Запрос другой модели или погодных наблюдений как fallback отсутствует.

## Проверка в этом окружении

Модуль покрыт автономными тестами `tests/test_weather.py` с искусственными
ответами: выбор запуска, часовые границы, кеш/refresh, целостность, единицы,
пропуски, две турбины, ограничение повторных запросов и явная маркировка
неподтвержденной исторической доступности.

Реальный HTTP smoke-запрос к архиву за 31 января 2026 был предпринят, но
заблокирован сетевой песочницей (`WinError 10013`). Повторный запрос с повышенными
разрешениями ожидал согласования и был прерван. **Живой ответ погодного API в
этом окружении не проверен.** Прохождение автономных тестов этого не заменяет.
